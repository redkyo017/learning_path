# Practice Track — file ops, nvim editing, nvim file ops (design + plan)

**Why:** a 2026-10-06 audit confirmed the gap the learner felt. `content/primers/file-ops-reference.md`,
`nvim-cheatsheet.md` and `nvim-file-ops.md` are references (0 drills, 0 hints). Day 1's "nvim survival hour"
says "work through the cheatsheet" with no practice files; Day 3 exercises 7–9 are mostly "explain why";
Day 7's nvim exercises are one-line tasks with no practice files and no way to check a result.
**Goal:** a graduated, hands-on, self-checking practice track the learner can repeat until fluent.

## Design

- Location: `linux_ops_mastery/labs/practice/` with three self-contained workbooks:
  `fileops/`, `nvim/`, `nvimfile/`, plus `labs/practice/README.md` (track overview) and
  `labs/practice/lib.sh` (shared host-side helpers).
- Each workbook: `README.md` (drills), `SOLUTION.md` (worked solutions + why), `setup.sh`, `check.sh`.
- Run from the course root on the Mac (like every other lab):
  `bash labs/practice/<wb>/setup.sh <N|all>` seeds/resets drill N's files inside `ws`;
  the learner works inside `ws` (`docker compose -p linuxops -f labs/fleet/docker-compose.yml exec ws bash`);
  `bash labs/practice/<wb>/check.sh <N|all>` prints `PASS dNN …` / `FAIL dNN: <what is wrong>` and exits non-zero on any FAIL.
- Practice files live in `ws:/root/practice/<wb>/dNN/` — NEVER under `/tmp` (nvim 0.9.5 `backupskip=/tmp/*`
  makes every write there in-place, which would falsify the `:w` inode drills). `/labs` is read-only in `ws`,
  so seeds are generated by `setup.sh` (heredocs / small generators), not copied from the repo at run time.
- Drill levels (progressive): **L1 guided** (exact commands/keystrokes given, learner types them and observes),
  **L2 hinted** (goal + numbered steps without the answer + collapsed hint), **L3 challenge** (goal and
  constraints only, e.g. "one ex command", "≤ 12 keystrokes"). Every drill: Goal, Setup command, Steps,
  "You should see", Check command, `<details><summary>Hint</summary>…</details>`, link to its SOLUTION section.
- Self-checking invariant (the acceptance test for every checkable drill):
  fresh `setup.sh N` → `check.sh N` FAILS; apply the SOLUTION → `check.sh N` PASSES.
  nvim editing solutions are proven by running the solution keystrokes headlessly in `ws`, e.g.
  `nvim --headless -c 'exe "normal! <keys>"' -c 'wq' file` (or `-c '<ex cmd>'`), then `check.sh`.
  Inode-semantics drills check with pinned fds or recorded inode + link count, not bare `stat -c %i`
  before/after (inode numbers get reused — pin with `exec 3<` or a hard link).
- A few drills may be "observe and explain" (not checkable) — mark them `Check: self` and keep them ≤ 20 %.
- Busybox contrast drills run in `slim` (`docker compose ... exec slim sh`), clearly labelled.
- Style: same voice as the course (concise, operator-focused, no flag catalogues — STRATEGY Mistake 1).
  Each workbook starts with `## Start here — plain steps` (5–8 plain steps) and ends with `## Stuck? Hints`.
  Every command block works pasted into zsh on the Mac (host side) or bash in `ws` (say which).

## Global constraints (all tasks)

- Course root: `/Users/hunghd/git_clone/learning_path/linux_ops_mastery`. Edit only the files your task lists.
- Fleet: `docker compose -p linuxops -f labs/fleet/docker-compose.yml up -d ws slim`. Reuse `labs/lib/common.sh`
  (`compose`, `in_ws`, `in_slim`, `require_fleet`) from the scripts. Scripts: `#!/usr/bin/env bash`, `set -euo pipefail`,
  `bash -n` clean, idempotent, work from any cwd.
- Live verification is required: run every drill's setup → check (FAIL) → solution → check (PASS) in `ws`,
  record the evidence in your report; `setup.sh all` then `check.sh all` must show all FAIL (except `Check: self`),
  and after all solutions all PASS. Clean up `/root/practice/<your wb>` at the end. No git, no subagents.
  Use `/usr/bin/grep` on the Mac. Never touch other containers or other workbooks' directories.
- Don't duplicate the primers: drills link to the primer section they practise (`content/primers/…#section`).

## Tasks

### Task 1: Shared harness + track README
Files: create `labs/practice/README.md`, `labs/practice/lib.sh`.
- `lib.sh` (sourced by workbook scripts after `common.sh`): `drill_dir <wb> <N>` → `/root/practice/<wb>/dNN`;
  `reset_drill <wb> <N>` (rm -rf + mkdir in ws); `pass <id> <msg>` / `fail <id> <msg>` (tally, colour-free);
  `finish` (prints `N/M passed`, exit 1 if any fail); `arg_drills <arg> <max>` expanding `all` or a number;
  `ws_file_eq <path> <expected-heredoc-var>` (exact compare with a unified diff on mismatch).
  Self-test it live with a throwaway workbook dir under /root/practice/_selftest (then delete).
- `README.md`: what the track is, which workbook to do when (map: fileops ↔ Day 1/3 + file-ops-reference;
  nvim ↔ Day 1 survival hour + Day 7 + nvim-cheatsheet; nvimfile ↔ Day 3/7 + nvim-file-ops), Start here
  (fleet up, enter ws, setup/check loop), levels L1–L3, a suggested schedule (e.g. 20–30 min daily reps),
  "repeat a drill until you can do it from memory" guidance, and a progress checklist table per workbook
  (filled in as Tasks 2–4 land — leave a placeholder table with drill ids TBD).

### Task 2: Workbook `fileops` (14–16 drills)
Files: `labs/practice/fileops/{README.md,SOLUTION.md,setup.sh,check.sh}`.
Progression (adapt counts): L1 read/inspect (head/tail/less +F/`sed -n`/`wc`/`file`/`stat`), search (`grep -rn`,
`-l`, `-c`, `-v`, `-E`, `zgrep`, `find -name/-mtime/-size/-newer -print0 | xargs -0`), write/create (`>`,
`>>`, `tee`, `tee -a`, heredoc, `install -m`, `mktemp`), update/replace (`sed -i` incl. a capture group,
`sed -n p` dry-run first, `awk` field edit to a new file + atomic `mv`), copy/move/delete (`cp -a`, `cp --backup`,
`mv` same-fs vs rename semantics, `rm` safety with `--`, a dash-prefixed filename), inode semantics
(same-inode vs new-inode writers: `>`, `sed -i`, `cp`, `mv`, `install` — prove with a hard link / pinned fd;
`sort -u f > f` trap and the fix), permissions/ownership touch (`chmod` symbolic vs octal, umask effect),
one busybox contrast drill in `slim` (busybox `cp` replaces the inode, GNU truncates in place).
Each checkable drill's check verifies the end state (content, mode, link count, inode relationship).

### Task 3: Workbook `nvim` editing (18–20 drills)
Files: `labs/practice/nvim/{README.md,SOLUTION.md,setup.sh,check.sh}`.
Each drill: a seeded file (ops-flavoured: nginx/conf/yaml/log/shell snippets) + an exact expected result.
Progression: L1 movement & survival (open, `:q!`, `:wq`, hjkl/w/b/e/0/$/gg/G/`:N`/`%`, `f`/`t`, `/` `n` `*`),
operators + motions + counts (`dw`, `d$`, `cw`, `3dd`, `yyp`, `>>`, `.` repeat), text objects (`ciw`, `ci"`,
`di(`, `dap`, `cit` on an XML-ish line, `yi{`), visual & visual-block (`V` `>`, `Ctrl-v` column insert/append,
`gv`), registers (`"ayy`, `"ap`, `"0`, blackhole `"_d`), undo/redo/`U`, search-replace (`:s`, `:%s` with
`\v` groups, `&`, `c` confirm, range `:10,20s`, `:'<,'>s`), global (`:g/pat/d`, `:v/pat/d`, `:g/pat/normal A;`,
`:g/^$/d`), macros (`qa…q`, `@a`, `5@@`, recursive-free), sort/uniq (`:sort u`, `:sort n`), `:norm`, quickfix
(`:vimgrep` + `:cdo s///`) on a small tree. L3 challenges with keystroke budgets ("≤ 10 keystrokes").
Every solution must be proven headless in `ws` with the shipped init.lua and its result byte-identical to the
check's expected text (`check.sh` diff). Put keystroke solutions in SOLUTION.md exactly as typed, with notation
(`<Esc>`, `<C-v>`, `<CR>`).

### Task 4: Workbook `nvimfile` (10–12 drills)
Files: `labs/practice/nvimfile/{README.md,SOLUTION.md,setup.sh,check.sh}`.
Open at line/pattern (`nvim +N`, `+/pat`), read-only (`-R`, `E45`, `:w!`), `:w newname` vs `:saveas`, write a
range (`:10,20w part.txt`, `:w >> f`), read in (`:r file`, `:r !cmd`), filter (`:%!sort`, `:'<,'>!jq .`),
buffers & args (`:e`, `:ls`, `:b`, `:args *.conf` + `:argdo %s///e | update`), discard (`:e!`), root-owned file as
non-root (`:w !sudo tee % >/dev/null` — check whether ws has a non-root user + sudo; if not, create one in setup
or adapt to `su`/explain; prove the result), `:w` inode semantics (`backupcopy` — prove same-inode vs new-inode
writes with a hard link/pinned fd outside /tmp; how a running reader of the old inode is affected),
swap-file recovery (kill an nvim mid-edit — reuse the primer's E325 notes: zombie `--embed` child under ws's
PID 1 makes it say STILL RUNNING — design the drill around what really happens, `nvim -r`, `:recover`,
then delete the swap), `fileformat` (CRLF file → `:set ff=unix`), and one busybox `vi` contrast in `slim`.
