# Solution notes — Lab 30

## `kill_checklist`
Check that every key in `REQUIRED_KEYS` is present and raise `ValueError` naming all that are not, so the message contains `dsr` when `dsr` is missing. Then evaluate six rules in a fixed order and return the names of those that fail: `dsr < 0.95` (deflated_sharpe), `oos_sharpe < 0.5 * is_sharpe` (oos_decay), `net_sharpe <= benchmark_sharpe` (beats_benchmark), `n_trades < 30` (sample_size), `max_drawdown < -0.35` (drawdown), `breakeven_cost_bps < 2 * assumed_cost_bps` (cost_survival). Most common mistake: writing `<` for beats_benchmark, where a tie must fail, or testing the drawdown with a positive threshold (drawdowns are negative numbers). `test_each_rule` changes one value of a passing report and requires exactly one name back, so any off-by-one threshold or wrong order shows up there.

## `verdict`
One line: `"kill"` if `kill_checklist(r)` is non-empty, else `"paper-trade"`. Reuse the checklist rather than repeating the rules, so the two can never disagree. A common mistake is to return a bool; `test_good_strategy_passes` compares with the strings.

## `run_capstone`
Split at `cut = int(len(prices) * split)`. For each lookback run `backtest(prices, momentum_signal(prices, lb), 0)` on the whole series, then slice `strat_ret` to the in-sample rows and take the Sharpe; pick the best. Keeping the whole-series run and slicing is safe because the signal at row t uses only prices up to t. Deflate with `deflated_sharpe_ratio(sr_is, len(lookbacks), var_of_sharpes, n_is)` where every Sharpe is per-period (mean/std, no annualization) and `var_of_sharpes` uses `ddof=1`, falling back to `1e-6` when there is a single lookback. Then rerun the chosen lookback on the full series with costs, slice rows from `cut` onward for `net_sharpe` (which equals `oos_sharpe`: both are net, out-of-sample) and take buy-and-hold on the same rows for the benchmark. `n_trades` counts rows with non-zero turnover, `max_drawdown` comes from the costed equity curve, and `breakeven_cost_bps` from gross returns (`strat_ret + cost`) and turnover. Annualize reported Sharpes with `sqrt(periods_per_year)`, but never feed annualized Sharpes to the DSR. Most common mistakes: choosing the lookback on the full sample (leaks the out-of-sample years), passing annualized Sharpes into the DSR (it then looks near 1.0 for anything), and benchmarking against the in-sample period. `test_run_capstone_produces_full_report` checks the keys, `0 <= dsr <= 1` and `max_drawdown <= 0`; the unit tests on `kill_checklist` do not catch a leak, so read your own pipeline for it.

## What the output means
On the snapshot, SPY (5 bps) picks the 120-day lookback in-sample (annualized Sharpe 0.85) and keeps most of it out-of-sample (0.50, since 2018-01-16, a split date computed outside `main()`), well above half the in-sample value, with a DSR of 0.99, 157 switches, a worst drawdown of -25.5% and a breakeven cost of 112 bps against 5 assumed. It fails one rule: buy-and-hold had Sharpe 0.79 over the same out-of-sample years, so after costs the rule earned less risk-adjusted return than doing nothing. That is the Day 25 finding reappearing: trend rules on SPY buy drawdown protection, not Sharpe. BTC-USD (10 bps, 365-day annualization) picks 20 days with an in-sample Sharpe of 1.74, which falls to 0.44 out-of-sample (below half, so oos_decay fails), trails buy-and-hold (0.47) and has a -54% drawdown. Its DSR of 1.00 is a reminder of what the DSR measures: with five similar trials and a long sample, the in-sample winner is unlikely to be luck within that sample; it says nothing about the next regime. Both verdicts are "kill", which is a normal outcome of the process.
