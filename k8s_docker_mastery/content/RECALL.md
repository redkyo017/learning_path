# Recall Drills

Cumulative retrieval practice for the 7 days. The learner's goal is to *consolidate*, and re-reading does not do that; answering from memory does. Use each section after its day, then follow the schedule.

## How to use this file

1. **Closed book.** Cover the answers. Write or say your answer for each question *before* opening its `<details>`.
2. **Grade yourself honestly:** full / partial / miss. Put a mark next to partial and miss.
3. **Re-test the misses**, not the whole file.
4. **Verify, do not just recall:** questions marked *(verify)* have a command that proves the answer on your cluster; run it once.

## Day 1: Docker internals and images

1. A container runs as root inside. Is that root on the host? What would change it? <details><summary>Answer</summary>Yes by default: the user namespace is the one of eight namespaces (mnt, pid, net, ipc, uts, user, cgroup, time) not enabled by default. `userns-remap` or rootless mode maps it to an unprivileged host UID. Defence otherwise: capabilities, seccomp, non-root `USER`.</details>
2. What is the kernel doing when a container with `--memory=32m` allocates beyond it, versus when it uses more CPU than `--cpus` allows? <details><summary>Answer</summary>Memory: `memory.max` is a hard cap; unreclaimable usage triggers the cgroup OOM killer (SIGKILL, exit 137, `OOMKilled=true`). CPU: `cpu.max` quota per period; the process is throttled, never killed.</details>
3. Prove an OOM kill from outside the container. <details><summary>Answer</summary><code>docker inspect -f '{{.State.OOMKilled}} {{.State.ExitCode}}' &lt;c&gt;</code> prints <code>true 137</code>. *(verify)* Run a 32m container with `ENABLE_DEBUG_ALLOC=1` and call `/debug/alloc?mb=64`.</details>
4. Why does `GOMEMLIMIT=28MiB` not save a 32 MB container from a 64 MB live allocation? <details><summary>Answer</summary>It is a soft target for the garbage collector. Live, referenced data cannot be collected, so the heap still exceeds the cgroup limit and the kernel kills it.</details>
5. `docker stop` takes 10 seconds and the exit code is 137. Diagnose and fix. <details><summary>Answer</summary>PID 1 is a shell or wrapper that did not forward SIGTERM; after the grace period Docker sent SIGKILL. Check `docker top` / `docker logs`. Fix: exec-form `ENTRYPOINT`, `exec "$@"` in scripts, `--init` if subprocesses are spawned. The same trap appears in Kubernetes as a 30 s pod termination.</details>
6. Why is a `RUN rm -rf /big` in a later layer not shrinking the image? <details><summary>Answer</summary>Layers are immutable and additive; the later layer only adds a whiteout. Delete in the same `RUN`, or use a multi-stage build and copy only artifacts.</details>
7. Order the Dockerfile for the best cache hit rate for a Go service, and say what the glob in `COPY go.mod go.sum* ./` is for. <details><summary>Answer</summary>Base → copy dependency manifests → `go mod download` → copy source → build. The glob lets it work whether or not `go.sum` exists (the course services have no dependencies). Add `RUN --mount=type=cache` so module/build caches persist across builds without entering the image.</details>
8. Why does the image use `USER 65532:65532` and not `USER nonroot`? <details><summary>Answer</summary>Kubernetes `runAsNonRoot` can only verify a numeric UID; a name causes `CreateContainerConfigError` ("cannot verify user is non-root"). `docker top` shows `65532` because the host has no passwd entry for it.</details>
9. What are the three object types of an OCI image, and what does an index add? <details><summary>Answer</summary>Manifest (layers + config reference), config (entrypoint, env, history, diff_ids) and layer blobs. An index maps platforms (and attestations such as SBOM/provenance) to per-platform manifests, so one tag serves amd64 and arm64.</details>
10. A secret passed as `ARG TOKEN` or `ENV` in the Dockerfile: what is the problem and the fix? <details><summary>Answer</summary>It is visible in `docker history` and image metadata and persists in layers. Use `RUN --mount=type=secret,id=...` for build time and runtime injection for running containers.</details>
11. On a Mac, why can you not `cat /proc/<pid>/ns` for a container process, and how do you get there? <details><summary>Answer</summary>Containers run in Docker Desktop's Linux VM, not on macOS. Enter the VM's namespaces: <code>docker run --rm -it --privileged --pid=host --cgroupns=host alpine nsenter -t 1 -m -u -n -i sh</code>, then use the PID from <code>docker inspect -f '{{.State.Pid}}'</code>.</details>

## Day 2: Docker networking, volumes, Compose

1. What is at the other end of `eth0@ifN` in a container? <details><summary>Answer</summary>The host-side veth (interface index N in the engine host's namespace, the VM on Docker Desktop), attached to the network's Linux bridge.</details>
2. What answers a DNS query sent to 127.0.0.11, and what happens to unknown names? <details><summary>Answer</summary>dockerd's embedded resolver, reached through DNAT rules in the container's own namespace. Container/service names resolve to IPs per network; everything else is forwarded to the host's resolvers. The default `docker0` bridge has no name resolution; user-defined networks do.</details>
3. Two user-defined bridges: why can't their containers reach each other? <details><summary>Answer</summary>Isolation is firewall rules in the host namespace (a per-bridge `! -i br-X -o br-X -j DROP` rule in the `DOCKER` chain on Engine 28+, where `DOCKER-FORWARD` is the jump point into it; older engines used `DOCKER-ISOLATION-STAGE-1/2`), not L2 separation; the host would otherwise route between them. Name resolution is also per network.</details>
4. Does container-to-container traffic on the same bridge use published ports or DNAT? <details><summary>Answer</summary>No: it goes directly IP to IP. DNAT and `-p` mappings apply only to traffic entering from outside the bridge (and MASQUERADE to traffic leaving it).</details>
5. `pg_isready` says healthy but connections are refused. Why and how to fix it? <details><summary>Answer</summary>Without `-h` it checks the unix socket, which the entrypoint's temporary init server answers. Use `pg_isready -h 127.0.0.1` so it tests TCP on the final server.</details>
6. You changed an environment value and ran `docker compose restart svc`; nothing changed. <details><summary>Answer</summary>`restart` reuses the existing container, whose config was fixed at creation. `docker compose up -d svc` recreates it when the config hash differs. *(verify)* with `docker compose config svc` and `docker inspect`.</details>
7. State Compose's precedence for a variable inside a container, and what `.env` does. <details><summary>Answer</summary>`run -e` > service `environment:` > `env_file:` > image `ENV`. `.env` and the shell only feed `${VAR}` interpolation in the Compose file (shell beats `.env` beats `:-default`); a `.env` value reaches the container only if listed in `environment:`/`env_file:`.</details>
8. `down`, `down -v`, `down --rmi local`: what does each delete? <details><summary>Answer</summary>`down`: containers and networks. `-v`: also volumes (data loss). `--rmi local`: also locally built images. Never images or volumes by default.</details>
9. How do you inspect a named volume on Docker Desktop, and why can't you `ls /var/lib/docker/volumes` on the Mac? <details><summary>Answer</summary>The store lives inside the VM. Mount it into a helper: <code>docker run --rm -v &lt;vol&gt;:/data alpine ls -la /data</code>.</details>
10. A distroless container needs a network debug session. How, without a shell in the image? <details><summary>Answer</summary>Join its network namespace from another container: <code>docker run --rm -it --network container:&lt;name&gt; nicolaka/netshoot</code> (or the Compose `debug` profile with `network_mode: service:&lt;svc&gt;`), or `docker debug`.</details>
11. Why bind published dev ports to 127.0.0.1 and use 15432 for Postgres? <details><summary>Answer</summary>`-p 5432:5432` publishes on all interfaces (LAN-exposed database); loopback binding limits it to your machine and a non-default host port avoids clashing with a local Postgres.</details>

## Day 3: Kubernetes core objects

1. Which component alone talks to etcd, and how do controllers learn about changes without polling? <details><summary>Answer</summary>kube-apiserver. Controllers use informers: one LIST, then a long-lived WATCH (resumable by resourceVersion) feeding a local cache and work queue.</details>
2. State the reconciliation loop and which controller creates pods from a Deployment. <details><summary>Answer</summary>Observe → diff desired vs actual → act → repeat. Deployment controller manages ReplicaSets; the ReplicaSet controller creates pods; the scheduler binds them; the kubelet runs them.</details>
3. You edit only `replicas`. Does a new ReplicaSet appear? What if you edit an env var? <details><summary>Answer</summary>`replicas` is not in the pod template: the same ReplicaSet is rescaled. A template change (env, image) gives a new template hash → new ReplicaSet and a rolling update.</details>
4. Bad image tag with `maxUnavailable: 0`: what do users see, and what does the Deployment do? <details><summary>Answer</summary>Nothing breaks: the new pod never becomes Ready, so old pods keep serving. After `progressDeadlineSeconds` the condition is `ProgressDeadlineExceeded` and `rollout status` exits non-zero; Kubernetes never rolls back by itself. `kubectl rollout undo` does.</details>
5. `kubectl delete deploy x --cascade=orphan`, then re-apply: what happens? <details><summary>Answer</summary>The Deployment is deleted; ReplicaSets lose their owner reference and everything keeps running. Re-applying creates a new Deployment that adopts the ReplicaSet with the matching template; no pods are recreated.</details>
6. Relabel one pod of a 3-replica ReplicaSet. How many run and who owns it? <details><summary>Answer</summary>Four: the ReplicaSet sees 2 matching and creates a third; the relabeled pod is orphaned (released), no longer in the Service, until deleted.</details>
7. A ConfigMap changes. Which consumers see it? <details><summary>Answer</summary>Env vars: never (fixed at start). A whole-directory volume mount: yes, after the kubelet sync delay (about 1-2 min) and only if the app re-reads. A `subPath` file: never. Use `kubectl rollout restart` or a checksum annotation to force a roll.</details>
8. Why does `rollout undo` show revision 4 where you expected 2? <details><summary>Answer</summary>Undo re-activates an old ReplicaSet under a new, higher revision number; the old number is consumed.</details>
9. Two reasons `:latest` is wrong that have nothing to do with `imagePullPolicy`. <details><summary>Answer</summary>A new image under the same tag produces no template change, hence no rollout; and nothing pins what runs, so pods may run different digests and undo returns to the same tag.</details>
10. What is a naked pod's failure mode versus a Deployment's pod? <details><summary>Answer</summary>A naked pod is not rescheduled or recreated when deleted, evicted or its node is lost. A controller recreates pods to match `replicas`.</details>
11. How do you see which pods a ReplicaSet owns and why a pod is garbage-collected with its owner? <details><summary>Answer</summary>`ownerReferences` (`kubectl get pod -o jsonpath='{.metadata.ownerReferences}'`); the garbage collector deletes dependents whose owners are gone (unless `--cascade=orphan`).</details>

## Day 4: Kubernetes networking, Gateway API, NetworkPolicy

1. Which component creates the pod's network interface? <details><summary>Answer</summary>The CNI plugin, invoked by the container runtime through CRI (not directly by the kubelet).</details>
2. Walk a ClusterIP packet through kube-proxy in iptables mode. <details><summary>Answer</summary>`KUBE-SERVICES` matches the ClusterIP:port → `KUBE-SVC-*` picks an endpoint (probabilistic) → `KUBE-SEP-*` does the DNAT to the pod IP. Balancing is per connection (conntrack). *(verify)* <code>docker exec desktop-control-plane iptables-save -t nat</code> on the kind provisioner.</details>
3. Why does a gRPC client keep hitting one pod after a scale-up? <details><summary>Answer</summary>The ClusterIP balances connections, and gRPC reuses a single HTTP/2 connection. Use a proxy/gateway that balances per request (Envoy, GRPCRoute), headless service + client-side balancing, or a mesh.</details>
4. A Service returns 503 through the gateway but the pod is Running 1/1. First checks? <details><summary>Answer</summary>`kubectl get endpointslices -l kubernetes.io/service-name=<svc>` (empty = selector mismatch, or 0 ready), and the route status (`BackendsAvailable=False / EndpointsNotFound`). An empty slice gives an immediate 503 from Envoy.</details>
5. Name the three Gateway API roles and who owns each. <details><summary>Answer</summary>GatewayClass (infrastructure provider), Gateway (platform team; listeners and `allowedRoutes`), routes such as HTTPRoute/GRPCRoute (app teams; matches, weights, filters). `ReferenceGrant` allows cross-namespace references.</details>
6. Two HTTPRoute rules both match `/orders`: a header match and a weighted default. Which wins, and why not rule order? <details><summary>Answer</summary>The header-match rule: Gateway API precedence is by specificity (exact path > longer prefix > method > more header matches > more query matches), not order.</details>
7. In a NetworkPolicy, one `from` item with a `namespaceSelector` and a `podSelector` versus two items? <details><summary>Answer</summary>One item = AND (pod with that label in that namespace); two items = OR (anything in that namespace, or that label in the policy's own namespace).</details>
8. After egress default-deny, what breaks first and what is the fix? <details><summary>Answer</summary>DNS: pods cannot reach CoreDNS; calls fail with `context deadline exceeded`. Allow UDP and TCP 53 to `k8s-app=kube-dns` in `kube-system`, then allow the specific downstreams.</details>
9. How do you prove NetworkPolicy is enforced on your cluster? <details><summary>Answer</summary>Test both paths from a client with the pod's labels (`kubectl debug --image=curlimages/curl`): allowed path succeeds, blocked path times out. The kubeadm provisioner ignores policies; if kindnet's agent wedges, `kubectl rollout restart ds/kindnet -n kube-system`.</details>
10. Why must the policy admit traffic from `envoy-gateway-system`? <details><summary>Answer</summary>Envoy Gateway runs the data-plane proxy pods in its own namespace, and they connect to pod IPs from EndpointSlices; those connections are what the pod's ingress policy sees.</details>
11. `ndots:5` consequence? <details><summary>Answer</summary>A name with fewer than 5 dots is tried with each search domain first, so external names cause several failed lookups; lower `ndots` via `dnsConfig` or use a trailing dot where safe.</details>
12. Why is ingress-nginx not the course's edge? <details><summary>Answer</summary>The community project was retired (March 2026) and had the critical IngressNightmare CVE; annotation-based config is non-portable. Gateway API has typed, role-split resources.</details>

## Day 5: Storage, security, RBAC

1. What does an unlabeled namespace enforce, and which common `restricted` assumption is false? <details><summary>Answer</summary>`privileged`, i.e. nothing. `readOnlyRootFilesystem` is not in any Pod Security Standard.</details>
2. List the `restricted` requirements for a pod. <details><summary>Answer</summary>`runAsNonRoot: true` (numeric user), `allowPrivilegeEscalation: false`, seccomp `RuntimeDefault`/`Localhost`, `capabilities.drop: [ALL]` (only `NET_BIND_SERVICE` may be added), only safe volume types, plus all of baseline (no privileged, hostPath, hostNetwork).</details>
3. You `kubectl apply` a root StatefulSet into a `restricted` namespace and it "succeeds" but no pod appears. Where is the error? <details><summary>Answer</summary>PSA validates pods at creation; a template only generates warnings. The StatefulSet/ReplicaSet controller's `FailedCreate ... violates PodSecurity` event holds it (`kubectl describe`). Preview beforehand with `kubectl label --dry-run=server`.</details>
4. Why does `WaitForFirstConsumer` leave a PVC `Pending`, and why is that right? <details><summary>Answer</summary>The scheduler must pick a node/zone first so the volume is provisioned where the pod can run. The PVC binds when the first consumer pod is scheduled.</details>
5. A StatefulSet is deleted. What happens to its PVCs and data? <details><summary>Answer</summary>They stay (data safe, cost continues). `persistentVolumeClaimRetentionPolicy.whenDeleted/whenScaled` (GA 1.32) can change that.</details>
6. PVC deleted: `Delete` vs `Retain` reclaim? <details><summary>Answer</summary>`Delete`: PV and data are removed. `Retain`: data kept, PV `Released`, claimRef must be cleared before reuse.</details>
7. Why a busybox `fs-probe` container to check a read-only rootfs on a distroless pod? <details><summary>Answer</summary>The app image has no shell; a second container in the same pod with the same securityContext lets you try writes (`/` fails with `Read-only file system`, `/tmp` emptyDir works).</details>
8. What does a RoleBinding to ClusterRole `view` grant, and what does it exclude? <details><summary>Answer</summary>Read access in the RoleBinding's namespace only. It excludes Secrets and Role/RoleBinding objects, and all writes.</details>
9. List everything a ServiceAccount can do in a namespace. <details><summary>Answer</summary><code>kubectl auth can-i --list -n &lt;ns&gt; --as=system:serviceaccount:&lt;ns&gt;:&lt;sa&gt;</code>.</details>
10. Why is a secret as an env var worse than a mounted file? <details><summary>Answer</summary>Inherited by children, in `/proc/<pid>/environ`, crash dumps and `exec ... env`; no live update. Files can have mode restrictions and refresh (non-subPath).</details>
11. Why `automountServiceAccountToken: false` on order-api? <details><summary>Answer</summary>The app does not call the API; a mounted token is a credential a compromised process could use. Least privilege.</details>

## Day 6: Helm 4, patterns, graceful shutdown

1. What does `helm rollback 1` not restore, and which revision does it create after revisions 1-2? <details><summary>Answer</summary>PVC/database contents and CRDs (manifests only). It creates revision 3 ("Rollback to 1").</details>
2. Helm 4 names for `--atomic` and `--force`; what does `--wait` use? <details><summary>Answer</summary>`--rollback-on-failure` (implies `--wait`) and `--force-replace`. `--wait` uses kstatus (watcher); without it the default is `hookOnly`. Server-side apply is the default for new installs.</details>
3. Why must the template omit `replicas` when an HPA is enabled? <details><summary>Answer</summary>Both Helm and the HPA would own the field; every upgrade would reset the replica count. (Migration caveat: removing Helm's sole ownership dips to 1 replica once.)</details>
4. HPA shows `<unknown>`: two causes? <details><summary>Answer</summary>No CPU requests on a container in the pod, or metrics-server not working. Check `kubectl top pods`.</details>
5. What makes a container a native sidecar, and what do you gain? <details><summary>Answer</summary>An `initContainers` entry with `restartPolicy: Always` (GA 1.33): it starts before the app, is restarted if it exits, and stops after the app containers. Its requests count in the pod's total.</details>
6. Init container vs hook Job for a schema migration? <details><summary>Answer</summary>An init container runs per replica, concurrently, on every pod start. A `pre-upgrade`/`post-install` hook Job runs once per release operation; keep migrations backward compatible because rollback does not undo them.</details>
7. Which probe restarts the container and which removes the pod from endpoints? Where does a database check belong? <details><summary>Answer</summary>Liveness (and startup on failure) restart; readiness removes from endpoints. A dependency check belongs in readiness (or a circuit breaker), never liveness.</details>
8. Explain the endpoint-propagation race and give two fixes. <details><summary>Answer</summary>Endpoint removal and SIGTERM start in parallel; an app that stops accepting at once gets requests the gateway still routes to it. Fix: `lifecycle.preStop.sleep.seconds` (built in, works in distroless) and/or app-level drain (`/ready` to 503, keep serving `DRAIN_DELAY_SECONDS`).</details>
9. Size `terminationGracePeriodSeconds`. <details><summary>Answer</summary>Greater than preStop + drain delay + the app's shutdown timeout (+ margin); it counts from the start of termination including preStop. The chart refuses to render a too-short value.</details>
10. What does a PDB protect against, and what not? <details><summary>Answer</summary>Voluntary disruptions via the Eviction API (drain, upgrades). Not node failure, OOM kills or `kubectl delete pod`; it never creates replicas. Zero allowed disruptions blocks drains; `unhealthyPodEvictionPolicy: AlwaysAllow` avoids stalls.</details>
11. Requests > limits? <details><summary>Answer</summary>Rejected by the API server ("must be less than or equal to memory limit"); lower the request too.</details>
12. Why `ScheduleAnyway` on hostname in a topology spread on this one-node cluster? <details><summary>Answer</summary>A hard `DoNotSchedule` rule would leave replicas Pending where the topology key lacks domains; `ScheduleAnyway` is a preference.</details>

## Day 7: Observability, debugging, synthesis

1. Which exit code and Reason mean the runtime could not start the process, and why are there no logs? <details><summary>Answer</summary>`StartError`/exit 128 (`RunContainerError`): no process ever ran.</details>
2. How do you prove an OOM kill, and what will you not find? <details><summary>Answer</summary>`Last State: OOMKilled`, exit 137; kernel line via `kubectl debug node/... --profile=sysadmin` + `chroot /host dmesg`. No event, no log line.</details>
3. `ImagePullBackOff` with "pull access denied": first check? <details><summary>Answer</summary>Spelling of the repository and tag (Docker Hub says this for a missing tag), and that locally built images were loaded into the cluster.</details>
4. `CrashLoopBackOff`: what grows with each restart, RESTARTS or the delay? <details><summary>Answer</summary>RESTARTS goes up by one; the back-off delay doubles (10 s, 20 s, ... capped at 5 min, reset after 10 min healthy). It is a waiting state.</details>
5. From a distroless pod, how do you tell "DNS unreachable" from "wrong name"? <details><summary>Answer</summary>Ephemeral netshoot container, `nslookup`: timeout = DNS unreachable (egress policy, CoreDNS); `NXDOMAIN` = wrong name.</details>
6. Gateway 503 with empty body, pod Running: cause and proof? <details><summary>Answer</summary>No endpoints (selector mismatch): empty EndpointSlice, route `EndpointsNotFound`, Envoy answers itself. Empty-body 404 = no route; `404 page not found` = the app answered.</details>
7. If every endpoint of a backend is present but not ready, what does Envoy do? <details><summary>Answer</summary>Panic routing: below the default 50% healthy threshold Envoy ignores health and still sends traffic to all hosts (verified live); as soon as one pod is ready, traffic moves to it. Only an empty EndpointSlice produces the immediate 503. Keep at least 2 replicas.</details>
8. Why does `tcpdump` fail in an ephemeral container of a non-root pod? <details><summary>Answer</summary>The pod's `runAsUser` applies, so the process has no effective capabilities even with `NET_RAW` added; run as root with `--custom` (not allowed under `restricted`).</details>
9. `kubectl drain` evicted a pod: will it show `Evicted`? <details><summary>Answer</summary>No: drain uses the Eviction API (honours PDBs) and the controller recreates it. `Evicted` is the kubelet's node-pressure eviction.</details>
10. Where to rate-limit, and where do retries live? <details><summary>Answer</summary>Edge gateway for external identities, mesh for internal callers, app for business rules and load shedding. Retry only idempotent calls, in one layer, with backoff, a budget and per-hop timeouts (three layers each retrying 3 times = 27 attempts).</details>
11. Sidecar mesh vs ambient, and when not to adopt a mesh? <details><summary>Answer</summary>Per-pod proxy vs per-node L4 agent with optional L7 waypoint. Do not adopt for few services/one team: added control plane, upgrades and debugging layers.</details>
12. NetworkPolicy and mesh authorization: complementary or alternative? <details><summary>Answer</summary>Complementary: NetworkPolicy is L3/L4 by labels/IPs enforced by the CNI; mesh authorization is L7 by mTLS workload identity.</details>

## EKS appendix (optional)

1. Which add-on delivers credentials under Pod Identity and what proves it worked? <details><summary>Answer</summary>`eks-pod-identity-agent`; the pod has `AWS_CONTAINER_CREDENTIALS_FULL_URI`, and `sts get-caller-identity` shows the role.</details>
2. What does the role trust, and what binds it to a ServiceAccount? <details><summary>Answer</summary>`pods.eks.amazonaws.com` (`sts:AssumeRole`, `sts:TagSession`); a Pod Identity association (cluster + namespace + ServiceAccount → role). No OIDC provider or annotation.</details>
3. When is IRSA still right? <details><summary>Answer</summary>Fargate pods, legacy SDKs, clusters outside EKS.</details>
4. What creates the ALB from an Ingress? <details><summary>Answer</summary>The AWS Load Balancer Controller (needs its own IAM policy/role association). Delete the Ingress while it still runs and verify the ALB, target groups and security group are gone before deleting the cluster.</details>
5. What do Auto Mode and Karpenter each decide? <details><summary>Answer</summary>Auto Mode: AWS operates nodes and core controllers. Karpenter: which instances to launch for pending pods and when to consolidate; it runs inside Auto Mode or standalone.</details>
6. Cost rule of thumb? <details><summary>Answer</summary>About $0.30-0.40 per hour (about $7-10 per day) while the cluster exists; a forgotten NAT gateway or ALB keeps billing.</details>

## Final 20-question mixed self-test

Closed book, 30 minutes, no commands until you have written all answers. Pass: 16/20 with the mechanism.

1. A container is killed with exit 137 and `OOMKilled=false`. What else produces 137, and how do you tell? <details><summary>Answer</summary>SIGKILL after the grace period expired (a PID 1 that ignores SIGTERM; `docker stop` took the full timeout / pod termination took the full grace). `OOMKilled` false and a delay equal to the grace period distinguish it.</details>
2. Why do pods that run as `USER nonroot` (name) fail `runAsNonRoot`, and what is the fix? <details><summary>Answer</summary>Kubernetes can only verify numeric UIDs: `CreateContainerConfigError`. Use `USER 65532:65532` or `runAsUser`.</details>
3. A pod in a `restricted` namespace is "created" by `apply` but never appears. Where do you look? <details><summary>Answer</summary>Events of the owning ReplicaSet/StatefulSet (`FailedCreate ... violates PodSecurity`); fix allowPrivilegeEscalation, capabilities, seccomp, numeric non-root user.</details>
4. NetworkPolicy objects exist but nothing is blocked. Three possible causes? <details><summary>Answer</summary>CNI does not enforce (kubeadm provisioner), the pod is not selected for that direction in `policyTypes`, or another policy's union of allows admits it. Also a wedged kindnet.</details>
5. Writes to a ConfigMap-backed file never appear in the pod. Cause? <details><summary>Answer</summary>`subPath` mount (or env var). Whole-directory mounts update after about a minute and the app must re-read.</details>
6. A rolling update drops a few requests despite passing readiness probes. Explain and fix. <details><summary>Answer</summary>Endpoint removal races SIGTERM; add `preStop.sleep` and/or app drain, with a sufficient grace period.</details>
7. HPA `<unknown>` and `kubectl top` fails. Fix order? <details><summary>Answer</summary>Check metrics-server (`kubectl apply -f labs/shared/metrics-server.yaml`, wait about a minute; needs `--kubelet-insecure-tls` on Docker Desktop), then CPU requests on every container.</details>
8. What does `helm upgrade --wait --rollback-on-failure` do on a bad readiness path? <details><summary>Answer</summary>Waits for readiness; on timeout rolls back to the previous revision (creating a new one). Helm 3 name: `--atomic`.</details>
9. Why can an Envoy-based gateway still route to pods that are all not ready, and what 503 comes only from "no endpoints"? <details><summary>Answer</summary>Panic routing. Empty EndpointSlice (selector mismatch/0 replicas) gives the immediate direct-response 503.</details>
10. A `Pending` pod: list four causes and the one command. <details><summary>Answer</summary>Insufficient requested CPU/memory, node selector/affinity, untolerated taint, unbound PVC (`WaitForFirstConsumer` with no consumer, missing StorageClass). `kubectl describe pod` → `FailedScheduling`.</details>
11. Debug a crash-looping distroless pod without rebuilding it. <details><summary>Answer</summary>`kubectl logs --previous`; `kubectl debug <pod> --copy-to=... --container=... --image=busybox --profile=general -- sleep 3600`; or an ephemeral netshoot container with `--target`.</details>
12. Why does `kubectl port-forward` success not prove your NetworkPolicy or route is right? <details><summary>Answer</summary>It tunnels via the API server/kubelet, bypassing the gateway and ingress policy path.</details>
13. How do the Docker Desktop kind and kubeadm provisioners differ for this course? <details><summary>Answer</summary>kind: images must be loaded (`load-images.sh`), kindnet enforces NetworkPolicy, node `desktop-control-plane`. kubeadm: images visible directly, no NetworkPolicy enforcement, node `docker-desktop`.</details>
14. A StatefulSet and its PVC: what survives which deletion? <details><summary>Answer</summary>Pod delete: PVC and data persist and the pod reattaches. StatefulSet delete: PVCs persist (default retention `Retain`). PVC delete: depends on reclaim (`Delete` loses data, `Retain` keeps PV `Released`).</details>
15. Why must liveness never include a database check, with an example failure? <details><summary>Answer</summary>A DB outage fails liveness on all pods; the kubelet restarts all of them and the cold-start storm worsens it. Put it in readiness.</details>
16. How does an HTTPRoute canary with a header override work, and how do you roll it back? <details><summary>Answer</summary>A more specific header-match rule sends testers to the canary; the default rule splits by relative weights (90/10). Roll back by setting the canary weight to 0 (or removing the backend).</details>
17. A pod has memory and CPU limits on every container and no requests. Which QoS class, and why? <details><summary>Answer</summary>Guaranteed: when only limits are set, requests default to the limits, so requests == limits for CPU and memory on every container. If any container lacks one of them it is Burstable; with nothing set, BestEffort. Under node memory pressure eviction goes BestEffort, then Burstable, then Guaranteed.</details>
18. Where would you rate-limit an external partner API vs protect an internal dependency from a noisy caller? <details><summary>Answer</summary>Edge gateway policy (per client/API key) for external; mesh policy by workload identity (or app load shedding) for the internal caller.</details>
19. Why delete the Ingress and verify the ALB is gone before deleting an EKS cluster? <details><summary>Answer</summary>The controller creates the ALB/target groups/security groups outside CloudFormation; deleting the cluster first orphans them, blocks VPC deletion and keeps billing.</details>
20. Explain "what happens when I `kubectl apply` a Deployment" in five steps. <details><summary>Answer</summary>API server validates/admits (PSA included) and stores in etcd → Deployment controller creates a ReplicaSet → ReplicaSet controller creates pods → scheduler binds pods to nodes by requests/affinity → kubelet asks the runtime (via CRI/CNI) to pull, start and probe containers; readiness adds them to EndpointSlices and gateway/kube-proxy pick them up.</details>
