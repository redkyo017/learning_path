# Glossary

Plain-English definitions of the terms the course uses, in alphabetical order. The day at the end of each entry is where the term is taught or used most. Day files and the primers in `primers/` carry the detail.

- **10.0.0.0/24 into four equal subnets** — The Day 2 split: borrow two bits to get four /26 subnets of 64 addresses each, 62 usable. (Day 2)
- **172.16.0.0/16 into eight** — The Day 2 split: borrow three bits to get eight /19 subnets, each with a block of 32 in the third octet. (Day 2)
- **192.168.10.0/24 unequal, 100 + 50 + 20 hosts** — The VLSM split: a /25, a /26 and a /27, placed largest first so each lands on its block boundary. (Day 2)
- **4789** — The UDP destination port for VXLAN. (Day 6)
- **6081** — The UDP destination port for GENEVE. (Day 6)
- **Access ISP** — The ISP that sells a customer the connection and owns the access network; it buys transit or peers upward. (Day 0)
- **Access point** — A device that bridges Wi-Fi (802.11) to Ethernet: a switch with a radio. Also written AP. (Day 0)
- **Access port** — A switch port that carries one VLAN untagged; the host attached to it never sees a tag. (Day 1)
- **ACK** — The TCP flag that says the acknowledgment number is valid; every segment after the first SYN carries it. (Day 3)
- **Active closer** — The TCP side that sends the first FIN. It is the one that ends up in TIME_WAIT. (Day 3)
- **Administrative distance (AD)** — A per-source trust rating a router compares before metrics: connected 0, static 1, eBGP 20, OSPF 110, iBGP 200. The lowest wins. (Day 5)
- **Advertising** — Telling a BGP neighbour about a prefix. A router advertises only what you configured and what is also in its routing table. (Day 5)
- **Age** — How long a forwarding database entry has gone unrefreshed; when it passes the ageing time the entry is dropped. (Day 1)
- **Anycast** — One address announced from several places, so the nearest one answers. DNS roots and some load balancers use it. (Day 6)
- **AP** — Access point; see Access point. (Day 0)
- **APIPA** — Automatic private IP addressing: the 169.254.0.0/16 address a host gives itself when DHCP gets no answer; it works only on the local link and has no gateway. (Day 0)
- **Application-level keepalive** — A heartbeat message your own protocol sends so a dead peer is noticed in seconds, instead of waiting for TCP keepalive. (Day 3)
- **Areas** — OSPF's way of limiting how far link-state floods travel. Area 0 is the backbone. (Day 5)
- **ARP** — Address Resolution Protocol: a broadcast that asks "who has this IPv4 address?" and gets back a MAC address. (Day 1)
- **ARP request** — A broadcast frame that asks which host owns an IPv4 address. See ARP. (Day 1)
- **AS_PATH** — The ordered list of ASNs a BGP route has crossed. It carries the loop check and the length rule. (Day 5)
- **ASN** — Autonomous system number, the identifier of a routing domain in BGP. Private ranges are 64512-65534 and 4200000000-4294967294. (Day 5)
- **Autonomous system** — A network run by one organisation under one routing policy, identified by an ASN. (Day 0)
- **Bandwidth-delay product** — Bandwidth times round-trip time: the amount of data in flight that the window must cover to fill a link. (Day 3)
- **BBR** — A congestion-control algorithm that estimates bottleneck bandwidth and round-trip time instead of reacting to loss. (Day 3)
- **BFD** — Bidirectional Forwarding Detection: a tiny hello protocol that reports a dead path in about a second, much sooner than BGP's hold timer. (Day 5)
- **BGP** — Border Gateway Protocol: the path-vector routing protocol between autonomous systems, run over TCP port 179. (Day 5)
- **Bit 0 (the I/G bit)** — The lowest bit of the first MAC byte: 0 is individual (unicast), 1 is group (multicast, and broadcast). (Day 1)
- **Bit 1 (the U/L bit)** — The next bit of the first MAC byte: 0 is universally administered (burned in by the vendor), 1 is locally administered. (Day 1)
- **Black hole** — A place where packets disappear with no error. An MTU black hole is the usual one: large DF packets vanish while small ones pass. (Day 2)
- **Block size** — 256 minus the mask octet value; the step between subnets in the octet that holds the boundary. Written as block size = 256 − mask octet value. (Day 2)
- **Bridge** — A Layer 2 device that learns source MACs and forwards frames by destination MAC. A Linux bridge is the lab's switch. (Day 1)
- **Bridge mode** — A setting that turns a combined modem-router into a modem only: no NAT, no DHCP, the public address passes through to the next device. (Day 0)
- **Broadcast domain** — The set of devices that receive each other's broadcast frames. A VLAN is one broadcast domain. (Day 1)
- **Bytes** — The unit TCP counts: sequence and acknowledgment numbers number bytes, not segments. (Day 3)
- **Cable** — Access over TV coax with DOCSIS: a cable modem talks to the CMTS, and the coax segment is shared among neighbours. (Day 0)
- **Caching and TTL** — A resolver keeps an answer for the record's TTL seconds, so a changed record reaches clients only as old copies expire. (Day 6)
- **CDN** — Content delivery network: a content network with its own ASN and servers close to users, connected at IXPs and inside access ISPs. (Day 0)
- **Cellular (4G/5G)** — Radio access to a carrier's core network; almost always behind CGNAT. (Day 0)
- **CGNAT** — Carrier-grade NAT: an ISP translating many customers, addressed from 100.64.0.0/10, onto a few public addresses. (Day 0)
- **Chain** — An ordered list of nftables rules, attached to a hook (a base chain) or reached by a jump. (Day 4)
- **Check the outgoing MTU** — The router step after the route lookup: if the packet is larger than the egress MTU and DF is set, drop it and send ICMP "fragmentation needed". (Day 2)
- **Child SA** — An IPsec security association that carries traffic, created under an IKE SA. A rekey replaces it with a new SPI. (Day 6)
- **CLOSE_WAIT** — The TCP state of the passive closer after it receives a FIN. A pile of CLOSE_WAIT sockets means the application forgot to call close(). (Day 3)
- **CMTS** — Cable modem termination system: the head-end device that talks to cable modems over the shared coax. (Day 0)
- **Congestion avoidance** — The TCP phase after slow start where the window grows by about one segment per round trip. (Day 3)
- **Congestion control** — The sender-side logic that limits data in flight to what the network can carry, using loss or delay as the signal. (Day 3)
- **Connected route** — A route created automatically when an interface gets an address, with administrative distance 0. (Day 2)
- **Conntrack** — The kernel's connection-tracking table. It records each flow's state so a stateful firewall and NAT can match return traffic. (Day 4)
- **Containment test** — Checking whether an address lies between a prefix's network and broadcast address. Compute the block, then compare. (Day 2)
- **Counters** — nftables counters record packets and bytes per rule, so you can see which rule a flow hit. (Day 4)
- **CUBIC** — The default Linux congestion-control algorithm: after a loss it grows the window along a cubic curve. (Day 3)
- **Decrement the TTL** — The router step that lowers the IPv4 TTL (IPv6 hop limit) by one and drops the packet when it reaches zero. (Day 2)
- **Default route** — The routing-table entry (0.0.0.0/0, or default) used when nothing more specific matches; on a laptop DHCP writes it from the router option. (Day 0)
- **DEI** — Drop eligible indicator: a one-bit field in the 802.1Q tag that marks a frame as discardable under congestion. (Day 1)
- **DF** — The IPv4 "do not fragment" flag. With DF set, a router that cannot fit the packet drops it and returns ICMP. (Day 2)
- **DHCP** — Dynamic Host Configuration Protocol: UDP 67 (server) and 68 (client); gives a host an address, mask, router, DNS server and lease. (Day 0)
- **DHCP relay** — A router function that forwards a client's DHCP broadcast as unicast to a server on another subnet and stamps the client's subnet (giaddr). (Day 0)
- **Direct Connect (DX)** — AWS's private link between your site and AWS. It speaks eBGP and is preferred over a VPN for the same prefix. (Day 5)
- **Discover** — The first DHCP message: a broadcast from 0.0.0.0 to 255.255.255.255 asking for any server. (Day 0)
- **Distance-vector** — A routing family where each router tells neighbours the cost to reach a prefix, without sharing a map. RIP is one; BGP is a related path-vector form. (Day 5)
- **DNAT** — Destination NAT: rewriting the destination address or port of a packet, as a port forward does. (Day 4)
- **DNS server** — The resolver address a DHCP option hands to a client; at home it is usually the router's forwarder. (Day 0)
- **DOCSIS** — The standard for data over cable-TV coax between a cable modem and the CMTS. (Day 0)
- **DORA** — The four DHCP messages: Discover, Offer, Request, Ack. (Day 0)
- **Double NAT** — Two address translations in one path, such as the home router and then the ISP's CGNAT; it blocks inbound connections and makes many customers share one public address. (Day 0)
- **DPD** — Dead peer detection: periodic IKE messages that let a VPN endpoint notice the other side is gone. (Day 6)
- **DSL** — Access over the telephone line, terminated at the exchange by a DSLAM; often with PPPoE. (Day 0)
- **DSLAM** — DSL access multiplexer: the exchange device that terminates many customers' DSL lines. (Day 0)
- **dst MAC** — The destination address in the Ethernet header. An unknown unicast destination is flooded. (Day 1)
- **eBGP and iBGP** — eBGP runs between ASes and changes the next hop and AS_PATH; iBGP runs inside an AS and changes neither. (Day 5)
- **ECMP and multipath** — Equal-cost multipath: installing several equally good routes and hashing each flow onto one, so packets of a flow stay in order. (Day 5)
- **ECS `awsvpc`** — The ECS network mode that gives each task its own ENI, so security groups and flow logs apply to the task. (Day 6)
- **EDNS0** — The DNS extension that lets UDP responses exceed 512 bytes, announced by the client in its query. (Day 6)
- **EKS VPC CNI** — The Kubernetes network plugin that gives each pod a real VPC IP address from the node's ENIs. (Day 6)
- **Encapsulation** — Each layer's header and data become the next layer's payload: HTTP in TCP in IP in Ethernet. (Day 0)
- **ENI trunking** — An ECS feature that raises the number of task ENIs a supported instance can hold. (Day 6)
- **Ephemeral port** — A short-lived client-side port chosen by the kernel for an outgoing connection, from a range such as 32768-60999. (Day 3)
- **ESP** — Encapsulating Security Payload: the IPsec protocol (IP protocol 50) that encrypts and authenticates packets. (Day 6)
- **EtherType** — The 16-bit Ethernet field that names the payload: 0x0800 IPv4, 0x0806 ARP, 0x86dd IPv6, 0x8100 a VLAN tag. (Day 1)
- **EVPN** — A BGP address family that distributes MAC and IP reachability for VXLAN overlays, replacing flood-and-learn. (Day 6)
- **Extension headers** — Optional IPv6 headers chained between the fixed header and the payload, each naming the next one. (Day 2)
- **Fast retransmit** — Resending a segment after three duplicate ACKs, without waiting for the retransmission timer. (Day 3)
- **FCS** — Frame check sequence: the 4-byte CRC at the end of an Ethernet frame. The NIC adds and checks it; tcpdump normally does not show it. (Day 1)
- **Fiber** — Access over glass: usually GPON, an ONT at home and an OLT at the ISP joined through a shared passive splitter. (Day 0)
- **Firewall** — A device that allows or drops flows by policy at L3 and L4 (more for next-generation boxes), usually tracking state. (Day 0)
- **First byte** — The first byte of a MAC address, which carries the I/G and U/L bits. (Day 1)
- **Flags** — The TCP control bits (SYN, ACK, FIN, RST, PSH, URG). Together they say what a segment is for. (Day 3)
- **Flood** — What a bridge does with a broadcast or an unknown unicast frame: send it out of every port except the one it arrived on. (Day 1)
- **Flow control** — The receiver limiting the sender through the advertised window, so a slow reader is not overrun. (Day 3)
- **Forward** — What a bridge does when it knows the destination: send the frame out of exactly one port. (Day 1)
- **Forwarding and conditional forwarding** — A resolver passing queries it cannot answer to another resolver, either always or only for chosen domains. (Day 6)
- **Forwarding database (FDB)** — The bridge's table of MAC address to port, built by learning source addresses. (Day 1)
- **Fragmentation needed and DF set** — ICMP type 3 code 4, sent when a packet with DF set is too big for the next link. It carries the next-hop MTU. (Day 2)
- **FRR default** — Since FRR 7.4, eBGP exchanges no routes until a policy is attached (bgp ebgp-requires-policy). The lab switches it off for brevity. (Day 5)
- **GENEVE** — An overlay encapsulation on UDP port 6081 with an extensible option field. AWS's Gateway Load Balancer uses it. (Day 6)
- **GPON** — Gigabit passive optical network: the fiber access standard with an OLT, passive splitters and ONTs. (Day 0)
- **Gratuitous ARP** — An ARP message a host sends about its own address, to refresh neighbours' caches after a move or failover. (Day 1)
- **GRE** — Generic Routing Encapsulation: a simple tunnel carried in IP protocol 47, with a 4-byte base header (24 bytes of overhead over IPv4). (Day 6)
- **Half-open** — A TCP connection one side believes is open while the other side no longer has it, for example after a crash. (Day 3)
- **Hold timer** — The BGP timer after which a silent neighbour is declared dead. Each side proposes one and the lower wins. (Day 5)
- **Hop 1 — the name (Day 6)** — First hop of the Day 7 request path: curl calls getaddrinfo, which reads resolv.conf and asks the resolver for the name. (Day 7)
- **Hop 2 — ARP to the gateway (Day 1)** — The client ARPs for its default gateway and learns the MAC to use as the Ethernet destination. (Day 7)
- **Hop 3 — the VPC router (Day 2)** — The VPC router strips the Ethernet header, looks up the destination, decrements the TTL and forwards. (Day 7)
- **Hop 4 — the TGW lookup and the clamp (Days 2, 3, 5)** — The transit gateway routes by its table and clamps the MSS so tunneled packets fit. (Day 7)
- **Hop 5 — encapsulation and MTU (Day 6)** — The GRE interface wraps the packet in a new outer header, which costs 24 bytes of MTU. (Day 7)
- **Hop 6 — the underlay (Day 2)** — The underlay is an ordinary routed link that sees only GRE between two outer addresses. (Day 7)
- **Hop 7 — decapsulate, then route (Days 2, 5)** — The far end removes the outer header and routes the inner packet again. (Day 7)
- **Hop 8 — the firewall and conntrack (Day 4)** — The forward chain accepts the new flow and conntrack records it so replies are allowed. (Day 7)
- **Hop 9 — the socket (Day 3)** — The SYN reaches a listener, the handshake completes and the application sees the connection. (Day 7)
- **Hub** — A layer-1 device that repeats every bit out of every other port; one collision domain. (Day 0)
- **iBGP** — BGP between routers in one AS. It keeps the next hop and does not re-advertise iBGP-learned routes to other iBGP peers. (Day 5)
- **ICMP** — Internet Control Message Protocol: the error and diagnostic messages of IP, such as echo, unreachable and time exceeded. (Day 2)
- **ICMP port unreachable** — ICMP type 3 code 3, sent when a UDP datagram arrives for a port nobody listens on. (Day 3)
- **ICMPv6 is mandatory** — IPv6 needs ICMPv6 for neighbour discovery and path MTU discovery. Filtering it all breaks the network. (Day 2)
- **Idle timeouts** — The time after which a firewall, NAT or load balancer forgets a silent flow, so a later packet is dropped or reset. (Day 3)
- **IGP metric** — The cost of reaching a BGP next hop through the interior routing protocol, used as a late tie-breaker. (Day 5)
- **IKEv2** — Internet Key Exchange version 2: the protocol that authenticates the VPN peers and sets up IPsec SAs. (Day 6)
- **IP exhaustion** — Running out of VPC addresses, often because pods or tasks each take one. Prefix delegation and secondary ranges relieve it. (Day 6)
- **IP-in-IP** — The simplest tunnel: an IP packet carried directly inside another, using IP protocol 4. (Day 6)
- **IXP** — Internet exchange point: a shared switch in one building where many ASes connect and peer. (Day 0)
- **Learn** — What a bridge does with a source MAC: record the address and the port it came from in the FDB. (Day 1)
- **Lease time** — The DHCP option that says how long the address is valid; renewal starts at T1 (50%) and rebroadcast at T2 (87.5%). (Day 0)
- **Link-local** — An address valid only on one link: fe80::/10 in IPv6 and 169.254.0.0/16 in IPv4. (Day 2)
- **Link-state** — A routing family where each router floods its own links and every router computes paths from the same map. OSPF and IS-IS are examples. (Day 5)
- **Load balancer** — A device that spreads connections (L4) or requests (L7) across servers. (Day 0)
- **Local-pref** — LOCAL_PREF: a BGP attribute, shared only inside one AS, that picks the exit. Higher wins, and it comes before AS-path length. (Day 5)
- **Local-pref beats AS-path** — The best-path order puts LOCAL_PREF before AS_PATH length, so a longer path with higher local-pref wins. (Day 5)
- **Longest-prefix match (LPM)** — The rule that, among all routes containing the destination, the one with the most prefix bits wins. (Day 2)
- **Look up** — The router step that finds the best route for the destination address before anything is forwarded. (Day 2)
- **Masquerade** — SNAT that uses the outgoing interface's current address, so you do not name it in the rule. (Day 4)
- **MED** — Multi-exit discriminator: a hint from a neighbour AS about which of its links to use. Lower wins, and it is non-transitive. (Day 5)
- **MED is polite, not binding** — MED is a hint compared only between paths from the same neighbouring AS, and the receiver may ignore it. (Day 5)
- **Messages** — The four BGP message types: OPEN, KEEPALIVE, UPDATE and NOTIFICATION. (Day 5)
- **MF** — The IPv4 "more fragments" flag. It is set on every fragment except the last. (Day 2)
- **Middlebox** — A device in the path, such as a firewall, NAT or load balancer, that can change or drop traffic. (Day 3)
- **Minimum** — The smallest datagram size every IPv6 link must carry: 1280 bytes. It floors the MTU you can rely on. (Day 6)
- **Modem** — A device that converts between the carrier's line signal (DSL, DOCSIS, radio) and Ethernet. It does not route. (Day 0)
- **MSS** — Maximum segment size: the largest TCP payload a host will accept, announced in the SYN. Usually the MTU minus 40 (IPv4). (Day 2)
- **MSS clamping** — Rewriting the MSS option in SYN packets so both ends choose segments that fit through a tunnel. (Day 2, Day 7)
- **MTU** — Maximum transmission unit: the largest IP packet a link carries without fragmenting. 1500 on standard Ethernet. (Day 1)
- **MTU rule** — A tunnel's inner MTU is the underlay MTU minus the encapsulation overhead, for example 1500 - 50 = 1450 for VXLAN. (Day 6)
- **NA** — Neighbour advertisement: the ICMPv6 reply to an NS, carrying the MAC address. (Day 2)
- **NAT** — Network address translation: rewriting addresses (and ports) as packets pass; many-to-one on a home router. (Day 0)
- **NAT-T** — NAT traversal: carrying ESP inside UDP port 4500 so IPsec survives a NAT in the path. (Day 6)
- **NDP** — Neighbour Discovery Protocol: IPv6's replacement for ARP, built on ICMPv6. (Day 2)
- **Negative caching** — Caching the fact that a name does not exist (NXDOMAIN), so repeated queries for it are answered locally. (Day 6)
- **Neighbour table** — The kernel's table of IP to MAC mappings, filled by ARP or NDP. Read it with ip neigh. (Day 1)
- **Next header** — The field that names what follows the header: the transport protocol in IPv6, or the next extension header. (Day 2)
- **NS** — Neighbour solicitation: the ICMPv6 query that asks who owns an address. It goes to a solicited-node multicast group. (Day 2)
- **Off by default** — TCP keepalive is disabled until an application turns it on with SO_KEEPALIVE. (Day 3)
- **Offer** — The second DHCP message: a server proposes an address and options to the client. (Day 0)
- **OLT** — Optical line terminal: the ISP-side device of a fiber access network that talks to many ONTs. (Day 0)
- **On loss** — What TCP does when a segment is lost: cut the congestion window (CUBIC by a factor, Reno by half) and retransmit. (Day 3)
- **ONT** — Optical network terminal: the box that ends the fiber at the customer's home, the fiber counterpart of a modem. (Day 0)
- **Options, set on the SYN and fixed for the connection** — TCP options such as MSS, window scale, SACK and timestamps are agreed on the SYN and cannot change later. (Day 3)
- **OSI model** — A seven-layer teaching vocabulary (physical to application); useful as shorthand once each layer is tied to a real header and device. (Day 0)
- **Path MTU discovery** — Finding the smallest MTU along a path by sending DF packets and reading the ICMP errors that come back. (Day 2)
- **Path-vector** — A routing type where each route carries the list of ASes it crossed. BGP uses it to avoid loops. (Day 5)
- **PCP** — Priority code point: the 3-bit field in the 802.1Q tag that carries a frame's class of service, 0 to 7. (Day 1)
- **Peering** — Two ASes exchanging traffic for their own customers only, usually at no charge (settlement-free). (Day 0)
- **Policy** — In nftables, the default verdict of a base chain (accept or drop) for packets no rule matched. In BGP, the route-maps that shape what is accepted and advertised. (Day 4)
- **Port translation** — Rewriting the TCP or UDP port during NAT, so many inside hosts can share one address. (Day 4)
- **Ports (16 bits each)** — TCP and UDP each carry a 16-bit source and destination port, 0 to 65535. With the addresses and protocol they form the 5-tuple. (Day 3)
- **PPPoE** — PPP over Ethernet: a login session used on many DSL lines; its 8-byte header lowers the usable MTU to 1492. (Day 0)
- **Preamble and start delimiter** — The 8 bytes that precede an Ethernet frame on the wire for clock synchronisation. The NIC strips them. (Day 1)
- **Prefix delegation** — In EKS, assigning a /28 (16 addresses) per ENI slot instead of one address, so a node can hold more pods. (Day 6)
- **Prefix length is not a BGP rule** — Longest-prefix match happens in the forwarding table before any BGP attribute is compared. (Day 5)
- **Prefix-list** — A BGP filter that matches prefixes and optional length ranges, such as 10.50.0.0/16 le 24. (Day 5)
- **Private and special ranges** — Addresses not routed on the public internet: 10/8, 172.16/12, 192.168/16, plus 100.64/10, 169.254/16 and 127/8. (Day 2)
- **RA** — Router advertisement: the ICMPv6 message in which a router announces prefixes and itself as a gateway. (Day 2)
- **Recursive vs authoritative** — A recursive resolver looks up names on behalf of clients; an authoritative server holds the actual records for its zones. (Day 6)
- **Repeater** — A layer-1 device that regenerates a signal to extend a link. (Day 0)
- **Reply** — The answer in a request-reply pair. An ARP reply is unicast and carries the sender's MAC. (Day 1)
- **Request** — The first half of a pair. An ARP request is a broadcast asking who has an address. In DHCP, the third message: the client broadcasts its choice of offer. (Day 0, Day 1)
- **Resolve the next hop** — The router step that finds the MAC for the next-hop IP, by ARP or NDP, before building the frame. (Day 2)
- **Rewrite the Ethernet header** — What each router does to a forwarded packet: new source MAC (its own) and new destination MAC (the next hop's). (Day 2)
- **Route reflectors** — An iBGP router that re-advertises routes between its clients, so you do not need a full mesh. (Day 5)
- **Route-map** — An ordered list of permit and deny clauses with matches and sets, used to filter and change BGP routes. It ends in an implicit deny. (Day 5)
- **Route-map clause** — One permit or deny entry in a route-map, with matches and sets, evaluated in sequence order. (Day 5)
- **Router** — A device that picks the next hop from the destination IP and the routing table, joining different networks. (Day 0)
- **RS** — Router solicitation: the ICMPv6 message a host sends to ask routers for an RA now. (Day 2)
- **RST** — The TCP flag that tears a connection down at once. It answers a segment for a closed port or an unknown connection. (Day 3)
- **Rules** — The match-and-action lines inside an nftables chain, evaluated in order until one gives a verdict. (Day 4)
- **SACK permitted** — A TCP option, negotiated on the SYN, that lets the receiver report non-contiguous blocks it holds, so only the gap is resent. (Day 3)
- **`search` and `ndots`** — Resolver settings: names with at least ndots dots are tried as-is first, otherwise each search suffix is tried first. (Day 6)
- **Sequence and acknowledgment numbers** — The 32-bit counters TCP uses to number bytes and confirm them. tcpdump shows them relative unless you use -S. (Day 3)
- **Sequence and acknowledgment numbers (32 bits each)** — The two 32-bit TCP counters in the header. Sequence numbers the first byte of the segment, acknowledgment says the next byte expected. (Day 3)
- **Sequence number** — In ESP, a counter that increases per packet; the receiver's replay window drops old numbers. (Day 6)
- **Sets** — nftables collections of addresses, ports or pairs that one rule can match against, instead of many rules. (Day 4)
- **Shared address space** — 100.64.0.0/10 (RFC 6598), reserved for carrier-grade NAT and not routed on the Internet. (Day 0)
- **Silence** — The failure mode of a dead TCP peer: nothing is sent, so without keepalive nothing notices. (Day 3)
- **Size** — How large a DNS answer is. Over 512 bytes without EDNS0 it is truncated (TC) and retried over TCP. (Day 6)
- **Size limit** — The upper bound on an nftables set or table's elements, set when you create it. (Day 4)
- **SLAAC** — Stateless address autoconfiguration: a host builds its own IPv6 address from an RA prefix and an interface identifier. (Day 2)
- **Slow start** — The TCP phase that begins with a small window and doubles it every round trip until loss or the threshold. (Day 3)
- **SNAT** — Source NAT: rewriting the source address of outgoing packets, as a NAT gateway does. (Day 4)
- **SPI** — Security Parameters Index: the 32-bit ESP field that tells the receiver which security association applies. (Day 6)
- **Split horizon** — Giving different DNS answers to different clients, for example private addresses to VPC clients and public ones outside. (Day 6)
- **State** — The conntrack state of a packet: new, established, related or invalid. Rules match on it. (Day 4)
- **Stateful** — A firewall that tracks connections, so reply traffic is allowed without its own rule. (Day 4)
- **Stateless** — A filter that judges each packet alone, with no memory of earlier ones, so the return direction needs its own rule. (Day 4)
- **Static route** — A route you write by hand. Administrative distance 1, and it beats eBGP for the same prefix. (Day 2)
- **Summarization** — Replacing several contiguous prefixes with one shorter prefix. It must be aligned and a power of two in size. (Day 2)
- **Switch** — A layer-2 device that forwards a frame toward the port that learned its destination MAC and floods unknown and broadcast frames. (Day 0)
- **SYN** — The TCP flag that opens a connection and carries the options (MSS, window scale, SACK, timestamps). (Day 3)
- **T1** — The DHCP renewal timer at 50% of the lease: the client asks the same server to renew. (Day 0)
- **T2** — The DHCP rebinding timer at 87.5% of the lease: the client broadcasts to any server. (Day 0)
- **Table** — The top-level nftables container, tied to an address family, that holds chains, sets and counters. (Day 4)
- **TC** — The DNS truncation flag: the answer did not fit, so the client should retry over TCP. (Day 6)
- **TCP** — Transmission Control Protocol: reliable, ordered byte streams over IP protocol 6, with handshake, flow and congestion control. (Day 3)
- **TCP keepalive** — Kernel probes on an idle connection to detect a dead peer. Off by default, and slow by default (about two hours). (Day 3)
- **TCP/IP model** — The four-layer model the protocols were built to: link, internet, transport, application. (Day 0)
- **The black hole** — The Day 2 failure where full-size DF packets are dropped silently because ICMP is blocked, while small packets still work. (Day 2)
- **Tier 1** — A network that reaches the whole Internet without buying transit, by peering settlement-free with every other Tier 1. (Day 0)
- **TIME_WAIT** — The state the active closer holds for about 60 seconds after closing, so late segments cannot corrupt a new connection. (Day 3)
- **TIME_WAIT lives on the active closer** — Whichever side sends the first FIN keeps the TIME_WAIT socket, so a busy client that closes first piles them up. (Day 3)
- **Timestamps (TS)** — A TCP option carrying send and echo times, used for round-trip measurement and protection against old duplicates. (Day 3)
- **TLV options** — Type-length-value fields: a flexible option format. GENEVE uses them to carry metadata. (Day 6)
- **TPID** — Tag protocol identifier: the 16-bit field, 0x8100 for 802.1Q, that marks a frame as VLAN-tagged. (Day 1)
- **Traceroute** — A tool that sends probes with rising TTL and reads the ICMP time-exceeded replies to list the hops. (Day 2)
- **Tracing** — Using nftables trace to print every chain and rule a packet meets, to see which one decided its fate. (Day 4)
- **Transit** — Paid service in which a provider carries a customer's traffic to the rest of the Internet. (Day 0)
- **Transit Gateway (TGW)** — An AWS regional router that connects VPCs, VPNs and Direct Connect through attachments and route tables, which behave like VRFs. (Day 5)
- **Transport** — The layer that carries the application's data. BGP uses TCP port 179 as its transport. (Day 5)
- **Transport mode** — IPsec mode that protects the payload and keeps the original IP header. Common between two hosts. (Day 6)
- **Trunk port** — A switch port that carries several VLANs, each frame tagged with its VID. (Day 1)
- **Tunnel mode** — IPsec mode that wraps the whole original packet in a new outer IP header. Used by gateway-to-gateway VPNs. (Day 6)
- **Two tuples** — A conntrack entry stores the original and the reply tuple. NAT changes one of them, which is how return packets find their way back. (Day 4)
- **UDP** — User Datagram Protocol: connectionless, unreliable datagrams over IP protocol 17, with an 8-byte header. (Day 3)
- **UDP 4500** — The port IPsec uses for NAT traversal: ESP packets are carried inside UDP datagrams to this port. (Day 6)
- **VID** — VLAN identifier: the 12-bit field in the 802.1Q tag, 1 to 4094. (Day 1)
- **VNI** — VXLAN or GENEVE network identifier: a 24-bit segment number, like a VLAN ID with 16 million values. (Day 6)
- **VRF** — Virtual routing and forwarding: a separate routing table on one router. TGW route tables behave like VRFs. (Day 5)
- **VTEP** — VXLAN tunnel endpoint: the device that adds and removes VXLAN encapsulation. (Day 6)
- **VXLAN** — A Layer 2 overlay on UDP port 4789 with a 24-bit VNI. It adds 50 bytes of overhead over IPv4. (Day 6)
- **Warm pool** — A set of spare VPC addresses the EKS CNI keeps ready, so a pod starts without waiting for an API call. (Day 6)
- **Why TIME_WAIT exists** — So the last ACK can be resent if lost, and so late segments from the old connection die out before the same 4-tuple is reused. (Day 3)
- **Window** — The 16-bit TCP field that tells the sender how many more bytes the receiver will accept. (Day 3)
- **Window (16 bits)** — The 16-bit window field: the receive window in bytes, at most 65535 unless window scale multiplies it. (Day 3)
- **Window scale** — A TCP option, sent on the SYN, that multiplies the window field by a power of two so windows can exceed 64 KB. (Day 3)
